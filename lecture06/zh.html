类与对象

把“数据”和“操作数据的函数”放进同一个结构。理解类、对象、引用和 UML，是后面继承与命名空间的基础。

对应讲义：Classes and Objects (CH18)

本章目标

  • 区分“类”和“对象”，能说出类声明包含哪两部分；
  • 用 class、类型化属性和 new 写出第一个可运行示例；
  • 理解对象变量保存的是对象的引用，而不是对象内容的拷贝；
  • 读懂 UML 类图中的 +、-、# 和属性类型。

1.1从“散装数据”到“对象”

假设你要表示一件商品。最直接的做法是用几个互不相关的变量：

$name = 'hammer';
$price = 9.99;

print $name . ' costs ' . $price;

只有一件商品时没问题。但商品一多，你就要维护多个数组，或者一堆带下标的变量；更麻烦的是，“商品能做什么”（打折、格式化价格、校验价格）散落在代码各处，和“商品有什么”分开了。

类（class）把这两件事放到一起：

  • 属性（properties）：对象“有什么”，例如名称、价格；在 PHP 里就是变量。
  • 方法（methods）：对象“能做什么”，例如读取名称、修改价格；在 PHP 里就是函数。

类本身只是蓝图，不会占用一个具体商品的位置；对象（object）才是按蓝图创建出来的实例。一个类可以创建任意多个对象，每个对象都有自己独立的一份属性值。

类（class）

  • 是定义、是模板；
  • 描述这一类对象共有的属性和方法；
  • 例如：Product 表示“商品”这个概念。

对象（object）

  • 是实例、是具体存在；
  • 拥有自己的属性值；
  • 例如：名称是 hammer、价格是 9.99 的那件商品。

1.2声明第一个类并创建对象

按照课程约定，类名和类声明文件名都以大写字母开头，类名使用 PascalCase（每个单词首字母大写）。把下面的代码保存为 src/Product.php：

<?php

class Product
{
    public string $name;
    public float $price;
}

逐行看：

  • class Product 声明了一个名为 Product 的类；
  • public 是可见性，表示类的外部也可以直接访问这个属性；
  • string 和 float 是属性的类型，PHP 会据此检查赋值；
  • $name、$price 是属性变量，声明时带 $。

然后在入口文件里引入类文件，用 new 创建对象：

<?php
require_once __DIR__ . '/../src/Product.php';

$product1 = new Product();
$product1->name = 'hammer';
$product1->price = 9.99;

print 'product 1 name = ' . $product1->name;

运行后输出：

product 1 name = hammer

这里发生了三件事：

  1. require_once 把 Product.php 读进来，让 PHP 知道 Product 这个类存在；
  2. new Product() 按蓝图创建一个对象，并把对象的引用赋给 $product1；
  3. $product1->name = 'hammer' 通过对象运算符访问属性并赋值。
易错点

访问对象属性时，属性名前面不加 $：写 $product1->name，不要写 $product1->$name。后者会被理解成“用变量 $name 的值作为属性名”，是另一回事。

命名与大小写

类名 Product 和文件名 Product.php 保持大小写一致。macOS 的文件系统默认不区分大小写，但部署到 Linux 服务器后，product.php 和 Product.php 是两个不同的文件，自动加载会直接失败。

1.3对象变量保存的是“引用”

讲义特别强调：$myObject 并不真正包含对象本身，而是保存了指向对象的引用。这意味着把一个对象变量赋给另一个变量时，复制的是“指向同一个对象的引用”，不是对象内容的副本：

$product1 = new Product();
$product1->name = 'hammer';

$product2 = $product1;          // 复制的是引用
$product2->name = 'saw';

print $product1->name;          // saw

输出是 saw，因为 $product1 和 $product2 指向的是同一个对象。只有显式使用 clone，才会得到一份属性值的拷贝：

$product2 = clone $product1;
$product2->name = 'saw';

print $product1->name;          // hammer

对象运算符 -> 用来访问属性或调用方法；“对象运算符”这个名字在讲义中也写作 arrow object operator。它和数组下标、命名空间的反对角线是三种完全不同的符号，初学时不要混用。

讲义用 UML 类图表示 Product：矩形分三栏，第一栏是类名，第二栏是属性，第三栏是方法（本例没有方法）。属性的写法通常是“可见性符号 + 名称: 类型”。

UML 是设计阶段的“共同语言”：它不关心 PHP 具体怎么写，只描述类与类之间的关系。后面继承、抽象类、protected 的图都会继续使用这套符号。

本章小结

  • 类 = 属性 + 方法；对象 = 按类创建出来的实例。
  • new ClassName() 创建对象，-> 访问属性或方法。
  • 对象变量保存引用；普通赋值不会复制对象，clone 才会。
  • 类名与文件名用 PascalCase，并保持大小写一致。

封装与访问器

把属性设为 private，让所有读写都经过方法。这样，校验规则只需要写在一个地方，对象就不会进入非法状态。

对应讲义：Private properties and accessor methods

本章目标

  • 说清为什么“公开属性”会破坏对象的一致性；
  • 写出规范的 getter / setter，并在 setter 中做校验；
  • 掌握 $this 的含义，以及 public / protected / private 的访问范围；
  • 避免“为每个属性机械生成 getter/setter”的坏习惯。

2.1为什么要把属性设为 private？

上一章的 Product 属性是 public，外部代码可以随手写：

$product1->price = -0.5;   // 负价格也能写进去
$product1->name = '';       // 空名称也能写进去

如果业务规则要求“价格不能为负”，你就必须在每一个给价格赋值的地方都检查一遍。只要漏掉一处，对象就可能带着非法数据继续运行，错误可能很晚才暴露。

把属性声明为 private 后，类外部不能直接读写它，只能通过公开的方法。这样，校验逻辑集中在 setter 里，对象的“不变量”（invariant）就能一直被维护：

$product1->setPrice(-0.5);  // setter 可以拒绝
$product1->price = -0.5;    // 直接报错：Cannot access private property
讲义的表述

“Declaring a property to be private is a good practice to enforce validation.”——把属性设为 private 是一种强制执行校验的好做法。它并不会自动校验，而是迫使所有外部访问都走你写好的方法。

2.2Getter 与 Setter：把访问变成方法

Getter 负责读取属性，setter 负责写入属性。它们统称为访问器（accessor methods）。下面是加了封装的 Product：

<?php

class Product
{
    private string $name;
    private float $price;

    public function getName(): string
    {
        return $this->name;
    }

    public function setName(string $name): void
    {
        $this->name = $name;
    }

    public function getPrice(): float
    {
        return $this->price;
    }

    public function setPrice(float $price): void
    {
        if ($price >= 0) {
            $this->price = $price;
        }
    }
}

几个关键点：

  • $this 代表“当前这个对象”。在方法内部访问自己的属性，必须写 $this->name，不能只写 $name（那只是方法的局部变量）。
  • 方法名后面的 : string、: float 是返回类型；: void 表示不返回任何值。
  • setPrice 只在价格大于等于 0 时赋值。输入非法时，属性保持原值，这就是校验。
  • getter 只负责读取，不修改状态；setter 只负责写入，并在这里集中校验。

用讲义中的测试脚本验证：

<?php
require_once __DIR__ . '/../src/Product.php';

$product1 = new Product();
$product1->setName('hammer');
$product1->setPrice(9.99);

print "(initial value) product 1 price = {$product1->getPrice()}";
$product1->setPrice(-0.5);
print '<br>(test 1) trying -0.5: ';
print "product 1 price = {$product1->getPrice()}";

$product1->setPrice(22);
print '<br>(test 2) trying 22: ';
print "product 1 price = {$product1->getPrice()}";

浏览器中的输出：

(initial value) product 1 price = 9.99
(test 1) trying -0.5: product 1 price = 9.99
(test 2) trying 22: product 1 price = 22

第二次调用 setPrice(-0.5) 时，条件不成立，属性没有被覆盖，所以仍然是 9.99。第三次传入 22，校验通过，价格更新为 22。

类型化属性的初始化

本例的 private float $price; 没有默认值。在第一次 setPrice() 之前读取 getPrice()，会得到 “Typed property must not be accessed before initialization” 错误。这是 PHP 在帮你发现“对象还没准备好”。可以给安全默认值，或在构造方法里强制初始化（第 3 章）。

2.3public、protected、private 的访问范围

访问位置publicprotectedprivate
声明它的类内部✓✓✓
继承它的子类内部✓✓✗
完全不相干的外部代码✓✗✗

讲义用一句话概括：protected 比 public 更严格，但比 private 更宽松。它的典型用途是“给子类用的内部实现”：外部不能碰，但继承家族内部可以共享。

可见性不是“安全加密”，而是设计边界。它告诉其他开发者：哪些东西是稳定接口，哪些只是内部细节。把内部细节藏起来，未来修改实现时就不容易破坏调用方。

设计建议

不要机械地给每个 private 属性都配一对 getter/setter。如果某个值只应该通过业务动作改变，就直接暴露业务方法，例如 deposit()、withdraw()、applyDiscount()。访问器是工具，不是目的。

本章小结

  • private 阻止外部直接读写，把访问集中到方法里。
  • getter 读取，setter 写入；校验放在 setter 中。
  • $this 指向当前对象；$this->price 访问属性。
  • public / protected / private 是设计边界，不只是语法限制。
小练习：BankAccount

写一个 BankAccount 类：private 属性 balance（float，初始 0）；提供 deposit(float $amount) 和 withdraw(float $amount)，要求金额必须大于 0，取款不能超过余额；提供 getBalance()。

<?php

class BankAccount
{
    private float $balance = 0.0;

    public function getBalance(): float
    {
        return $this->balance;
    }

    public function deposit(float $amount): void
    {
        if ($amount > 0) {
            $this->balance += $amount;
        }
    }

    public function withdraw(float $amount): void
    {
        if ($amount > 0 && $amount <= $this->balance) {
            $this->balance -= $amount;
        }
    }
}

构造方法与魔术方法

让对象一创建就处于可用状态：用 __construct() 初始化，用 __toString() 输出，用可空返回值和自定义方法表达更多信息。

对应讲义：Constructor magic method · __toString magic method and NULL reference · Custom method and virtual attributes

本章目标

  • 用 __construct() 接收参数并初始化属性；
  • 理解 PHP 8 的构造器属性提升，以及它绕过 setter 的取舍；
  • 用 __toString() 让对象可以直接被 print / echo；
  • 用 ?Type 和 null 表示“可能没有结果”；
  • 用自定义方法计算虚拟属性，而不是把派生数据存进属性。

3.1__construct()：对象出生时运行

PHP 的构造方法不叫类名，而是固定的魔术方法名 __construct()。每次执行 new Product(...) 时，PHP 会自动调用它，你不需要手动调用。

把参数传进构造方法，就可以在对象创建时完成初始化，避免“先 new，再逐个 set”的中间状态：

<?php

class Product
{
    private string $name;
    private float $price;

    public function __construct(string $name, float $price)
    {
        $this->setName($name);
        $this->setPrice($price);
    }

    public function getName(): string
    {
        return $this->name;
    }

    public function setName(string $name): void
    {
        $this->name = $name;
    }

    public function getPrice(): float
    {
        return $this->price;
    }

    public function setPrice(float $price): void
    {
        if ($price >= 0) {
            $this->price = $price;
        }
    }
}
require_once __DIR__ . '/../src/Product.php';

$product1 = new Product('hammer', 9.99);

print 'product 1 name = ' . $product1->getName();
print ", and price = {$product1->getPrice()}";

输出：

product 1 name = hammer, and price = 9.99

注意构造方法内部调用的是 setName() / setPrice()，而不是直接写 $this->price = $price。这样，setter 里的校验仍然生效，初始化路径和普通写入路径保持一致。讲义把这一点单独标了出来。

约定

讲义要求把 __construct() 声明在类的第一个位置。PHP 语法并不强制顺序，但把构造方法放在最前面，读者一眼就能看到“创建这个对象需要什么”。

如果价格非法

构造时传入负价格，setPrice() 会拒绝赋值，$price 保持未初始化。此后读取它会报错。更严格的做法是在 setter 中抛出异常，让创建直接失败，而不是留下一个半成品对象。异常处理超出本讲范围，知道这个方向即可。

3.2构造器属性提升（PHP 8+）

讲义提到可以用“promotion”简化类声明：在构造方法的参数前写可见性，PHP 会自动把参数声明成同名属性，并完成赋值。

class Product
{
    public function __construct(
        private string $name,
        private float $price
    ) {
    }

    public function getName(): string
    {
        return $this->name;
    }

    public function getPrice(): float
    {
        return $this->price;
    }
}

这段代码等价于“声明两个 private 属性 + 在构造方法里逐个赋值”，但短得多。适合属性较多、初始化逻辑简单的值对象。

取舍

属性提升会直接写入属性，不会经过 setter。如果价格必须校验，就不要只靠提升；可以在构造方法体内再调用校验方法，或者保留显式属性 + setter 的写法。简洁和可验证性需要权衡。

3.3__toString()：把对象变成字符串

当对象被放进字符串上下文（print、echo、字符串拼接）时，如果类定义了 __toString()，PHP 会自动调用它。方法必须返回 string：

public function __toString(): string
{
    return '(Product) name = ' . $this->name . ', and price = ' . $this->price;
}
$product1 = new Product('hammer', 9.99);
print $product1;
(Product) name = hammer, and price = 9.99

如果没有 __toString()，直接 print 一个对象会得到 “Object of class Product could not be converted to string” 的错误。它适合调试输出、日志摘要，不适合承载复杂业务逻辑。

3.4NULL、可空类型与虚拟属性

有些操作可能“查不到结果”，这时方法可以返回 null。在返回类型前加 ?，表示“这个类型或 null”：

public function blogFromId(int $id): ?Blog
{
    if ($id > 0) {
        return $this->blogRepository->find($id);
    }
    return null;
}

?Blog 读作 “Blog or null”。调用方必须先判断，再使用返回值：

$blog = $blogService->blogFromId(0);

if ($blog === null) {
    print 'Blog not found';
} else {
    print $blog->title;
}

讲义示例里用了 is_numeric($id)，但参数已经声明为 int，这个检查通常是多余的。真正重要的是：无法产生对象时，明确返回 null，并让调用方处理。

虚拟属性：算出来的信息

“虚拟属性”不是真的存了一个属性，而是用方法根据已有属性计算出一个新值。例如，只存出生日期，需要时计算年龄：

class Person
{
    public function __construct(private DateTimeImmutable $birthDate)
    {
    }

    public function age(): int
    {
        $today = new DateTimeImmutable('today');
        return $this->birthDate->diff($today)->y;
    }
}

$person = new Person(new DateTimeImmutable('2000-05-10'));
print $person->age();   // 例如 26

为什么不在构造时把 age 存成属性？因为年龄会随时间变化，存下来很快就会过期；而出生日期不会变，是真正的事实。虚拟属性把“会变化的数据”留给计算，避免同步问题。

调用时注意：age() 是方法，要写括号；不要写成 $person->age。如果希望像属性一样访问，也可以定义 getAge()，但本质上仍是方法调用。

本章小结

  • __construct() 在 new 时自动运行，用来建立有效状态。
  • 构造方法里调用 setter，可以复用校验逻辑。
  • 属性提升让声明更短，但会绕过 setter。
  • __toString() 必须返回字符串；?Type 表示可空。
  • 虚拟属性是算出来的，不需要存储。

继承与子类

把共同的属性和方法放进父类，让子类自动拥有它们，再添加自己特有的部分。继承表达的是“is-a”（是一种）关系。

对应讲义：Inheritance and Subclasses

本章目标

  • 解释“共享成员只定义一次”带来的好处；
  • 理解为什么类文件的加载顺序重要；
  • 知道 PHP 只支持单继承，并能判断什么时候不该用继承。

4.1extends：把共同部分抽上去

讲义用 Vehicle、Car、Boat 举例。三种交通工具都有型号、载客数和最高速度；Car 还有车身类型，Boat 还有注册国家。把这些共同成员放在 Vehicle 中，只定义一次：

<?php

class Vehicle
{
    public string $makeModel;
    public int $numPassengers;
    public float $topSpeed;
}

子类用 extends 继承它，只写自己特有的属性：

<?php

class Car extends Vehicle
{
    public string $bodyShape;
}
<?php

class Boat extends Vehicle
{
    public string $countryOfRegistration;
}

创建 Car 对象后，可以直接访问父类的属性：

<?php
require_once __DIR__ . '/../src/Vehicle.php';
require_once __DIR__ . '/../src/Car.php';

$car1 = new Car();

$car1->bodyShape = 'Sedan';
$car1->makeModel = 'Ford Mustang';
$car1->numPassengers = 5;
$car1->topSpeed = 150;

var_dump($car1);

var_dump() 会显示对象里一共有四个属性：bodyShape 来自 Car，另外三个来自 Vehicle。这就是“子类自动拥有父类的属性和方法”。

加载顺序

所有类文件都必须在主文件中读取，而且顺序重要：Vehicle 必须在 Car 之前被读取，因为 Car extends Vehicle。如果先读 Car.php，PHP 还不认识 Vehicle，就会报 “Class Vehicle not found”。第 7 章的 Composer 自动加载器会彻底解决这个问题。

4.2继承中的构造方法

如果子类没有定义构造方法，创建子类对象时会沿用父类的构造方法。如果子类定义了自己的构造方法，PHP 不会自动调用父类构造方法，需要显式写 parent::__construct(...)：

class Vehicle
{
    public function __construct(protected string $makeModel)
    {
    }
}

class Car extends Vehicle
{
    public function __construct(string $makeModel, public string $bodyShape)
    {
        parent::__construct($makeModel);
    }
}

$car = new Car('Ford Mustang', 'Sedan');

parent:: 是“作用域解析运算符”，表示“去父类里找这个方法”。它和 $this-> 的区别是：$this-> 调用当前类（可能已被重写）的方法，parent:: 明确调用父类版本。

如果子类构造方法忘了调用 parent::__construct()，父类中依赖构造初始化的属性就可能没有值。PHP 不会替你检查这一点，所以这是继承中最常见的坑之一。

4.3单继承：一个类只能有一个直接父类

PHP 允许一个类有多个子类，但每个类只能有一个直接父类。这避免了“这个属性到底从哪条继承线来”的歧义，但也让复杂的类层级更难设计。

Vehicle

topSpeed: Float

层级越深，越要小心设计：子类应该真正“是一种”父类。

判断是否该用继承，可以做一个简单的“is-a”测试：

  • Car is a Vehicle？是，合理。
  • MotorBoat is a Boat？是，合理。
  • Engine is a Car？不是，引擎是汽车的组成部分，应该用组合（一个类持有另一个对象），而不是继承。

如果两个类只是“有共同代码”，并不存在 is-a 关系，优先考虑组合或抽出一个更准确的共同父类。继承是很强的耦合：父类一改，所有子类都会受影响。

  • 共同成员只写一次，子类只写差异部分。
  • 父类文件必须先于子类文件加载。
  • 子类自定义构造方法时，记得调用 parent::__construct()。
  • PHP 单继承；继承前先确认 is-a 关系。

5.1protected：给继承家族的内部通道

protected 的属性或方法，对“类内部”和“继承它的子类”可见，但对项目中的其他代码不可见。它比 public 更严格，比 private 更宽松。

<?php

class Vehicle
{
    protected string $makeModel;
    private int $numPassengers;
    private float $topSpeed;

    public function getMakeModel(): string
    {
        return $this->makeModel;
    }

    public function setMakeModel(string $makeModel): void
    {
        $this->makeModel = $makeModel;
    }

    public function setNumPassengers(int $numPassengers): void
    {
        $this->numPassengers = $numPassengers;
    }

    public function setTopSpeed(float $topSpeed): void
    {
        $this->topSpeed = $topSpeed;
    }
}

子类 Car 可以直接读取 $this->makeModel，因为它是 protected：

5.2抽象类：只为被继承而存在

抽象类表示一个不完整的、概念性的父类。它不能被直接实例化，只负责把共同成员提供给子类。讲义中的 Vehicle 就是抽象类：现实项目里不会有一个“纯交通工具”，只会具体到汽车、船、飞机。

<?php

abstract class Vehicle
{
    protected string $makeModel;
    private int $numPassengers;
    private float $topSpeed;

    public function getMakeModel(): string
    {
        return $this->makeModel;
    }

    public function setMakeModel(string $makeModel): void
    {
        $this->makeModel = $makeModel;
    }
}
$vehicle = new Vehicle();   // Fatal error:
                            // Cannot instantiate abstract class Vehicle

抽象类还可以声明静态成员，用来表示“属于整个类而不是某个对象”的数据或工具方法。例如：

abstract class Vehicle
{
    protected static int $count = 0;

    public static function count(): int
    {
        return self::$count;
    }
}

此外，抽象类可以声明抽象方法：只写签名，不写实现，强制子类必须实现。这相当于一份“合同”：

abstract class Vehicle
{
    abstract public function maxSpeed(): float;
}

class Car extends Vehicle
{
    public function maxSpeed(): float
    {
        return 240.0;
    }
}

讲义强调：应该用 abstract 关键字明确表达一个类的用途。它不是为了“少写代码”，而是为了告诉读者：这个类不能单独使用，必须被具体子类补全。

5.3重写（Override）：子类给出自己的版本

重写就是：在子类中定义一个与父类同名的方法，从而替换继承来的行为。讲义用 Food 和 Dessert 演示：父类的 __toString() 输出 “(FOOD) 名称”，子类则输出 “I am a Dessert...”。

<?php

class Food
{
    protected string $name;

    public function __construct(string $name)
    {
        $this->name = $name;
    }

    public function __toString(): string
    {
        return "(FOOD) {$this->name}";
    }
}
<?php

class Dessert extends Food
{
    public function __toString(): string
    {
        $message = parent::__toString();
        $message .= " I am a Dessert!";
        return $message;
    }
}
$dessert = new Dessert('Tiramisu');
print $dessert;
(FOOD) Tiramisu I am a Dessert!

parent::__toString() 先执行父类版本，拿到 “(FOOD) Tiramisu”；然后 .= 把子类自己的文字追加进去。这样既保留了父类的输出格式，又加上了子类的差异，称为“增强继承行为”（augmenting inherited behavior）。

如果子类完全不想保留父类行为，也可以直接返回自己的字符串。但多数情况下，parent:: 能避免重复实现共同部分。注意：parent:: 只能调用父类方法，不能访问父类的 private 属性。

5.4里氏替换原则（LSP）

里氏替换原则（Liskov Substitution Principle，LSP）说的是：

定义

如果 Dessert 是 Food 的子类，那么任何使用 Food 的地方，都应该能够换成 Dessert，而不会产生意外行为。

换句话说，子类不只是“名字上属于父类”，还要在行为契约上真正可替换。父类承诺“输入什么、返回什么、抛出什么”，子类不能偷偷把承诺改得更苛刻。

讲义列出了四种允许的签名变化：

变化父类子类为什么安全
必填参数变可选validUser(int $minAge)validUser(int $minAge = 18)调用方仍然可以只传一个参数
增加可选参数validUser(int $minAge)validUser(int $minAge, int $maxAge = 65)新参数有默认值，旧调用不受影响
返回更具体的类型getRandomFood(): FoodgetRandomFood(): DessertDessert 也是 Food，调用方仍能当 Food 用（协变）
参数类型更宽松rate(Dessert $d)rate(Food $f)能接受更多输入，不会拒绝父类原本接受的参数（逆变）

协变：返回值更具体

class Food
{
}

class Dessert extends Food
{
}

class FoodFactory
{
    public function getRandomFood(): Food
    {
        return new Food();
    }
}

class DessertFactory extends FoodFactory
{
    public function getRandomFood(): Dessert
    {
        return new Dessert();
    }
}

调用方只知道自己在拿 Food，拿到 Dessert 当然也可以。返回值从宽变窄是安全的，这叫协变。

逆变：参数更宽松

class DessertCritic
{
    public function rate(Dessert $dessert): string
    {
        return 'Rated a dessert';
    }
}

class FoodCritic extends DessertCritic
{
    public function rate(Food $food): string
    {
        return 'Rated some food';
    }
}

父类版本只接受 Dessert；子类版本接受更宽的 Food。原本能传给父类的甜点，现在仍然能传，所以安全。参数从窄变宽，叫逆变。

反例：子类偷偷加要求

class FoodFactory
{
    public function make(string $name): Food
    {
        return new Food();
    }
}

class DessertFactory extends FoodFactory
{
    // 新增了一个必填参数：旧调用 make('Tiramisu') 会失败
    public function make(string $name, string $flavor): Food
    {
        return new Food();
    }
}

这不仅是设计问题，PHP 也会直接报 “Declaration of DessertFactory::make() must be compatible with FoodFactory::make()”。因为子类方法要求调用方多传一个参数，破坏了父类的调用契约。

LSP 还包括行为层面：子类不能突然抛出父类没有声明的新异常，不能把“成功返回”改成“返回 null”，也不能改变方法语义。PHP 只能检查签名，行为契约需要设计者自己保证。

5.5final：到此为止，不要再重写

在方法前加 final，子类就不能重写它：

class Product
{
    protected int $skuId;
    private string $description;

    public function __construct(int $skuId, string $description)
    {
        $this->skuId = $skuId;
        $this->description = $description;
    }

    final public function setSkuId(int $skuId): void
    {
        if ($skuId > 0) {
            $this->skuId = $skuId;
        }
    }
}

也可以把整个类声明为 final，表示不允许任何子类：

final class ApiResponse
{
    // ...
}

讲义建议：不要轻易把类设为 final，除非你有明确理由，例如：

  • 这是一个 API 库，你不希望使用者改变已声明的行为；
  • 你希望锁定实现，避免版本升级时因子类覆盖而出现意外后果。

对方法使用 final 通常比对整个类使用更常见：你可以允许继承，但禁止改动某个关键算法或安全校验。

本章小结

  • protected 对子类开放，对项目其他代码关闭；设计上仍优先走访问器。
  • 抽象类不能实例化，用来放共同成员和强制契约。
  • 重写用同名方法；用 parent:: 保留父类行为。
  • LSP：子类必须能在不改变预期行为的前提下替换父类。
  • final 阻止重写；对类使用要谨慎。

class Report

本章目标

  • 区分完全限定名、use 导入和当前命名空间；

6.1为什么需要命名空间？

假设你的项目里有一个 Shirt 类，第三方库也提供了一个 Shirt 类。如果两者都放在全局空间，PHP 会报 “Cannot declare class Shirt, because the name is already in use”。

命名空间（namespace）相当于给类加上一层“虚拟目录”。完整类名由命名空间和类名组成，用反斜杠分隔：

\MyNamespace\MySubNamespace\MyClass
└──────┬─────┘└──────┬──────┘└──┬──┘
    命名空间        子命名空间    类名

PHP 内置类（如 DateTime、Exception）位于根命名空间，可以用一个反斜杠表示：\DateTime。你自己的类则可以放在任意命名空间下。

声明命名空间时，namespace 必须是文件中的第一条 PHP 语句（declare(strict_types=1); 除外）：

<?php

namespace Mattsmithdev;

class Shirt
{
    private string $type = 't-shirt';

    public function getType(): string
    {
        return $this->type;
    }

    public function setType(string $type): void
    {
        $this->type = $type;
    }
}

这个类的完整名字是 Mattsmithdev\Shirt，而不是 Shirt。命名空间声明只影响当前文件，不会自动影响其他文件。

6.2完全限定名与 use

在另一个文件中使用这个类，有两种写法。

写法一：完全限定名

每次写完整名字，并以反斜杠开头，表示“从根命名空间开始找”：

$shirt1 = new \Mattsmithdev\Shirt();
$shirt2 = new \Mattsmithdev\Shirt();

print "shirt 1 type = {$shirt1->getType()}";

适合只使用一次的情况。名字很长，但意图最明确。

写法二：use 导入

在文件顶部用 use 把类导入当前文件，之后就可以直接写短类名：

use Mattsmithdev\Shirt;

$shirt1 = new Shirt();
$shirt2 = new Shirt();

print "shirt 1 type = {$shirt1->getType()}";

use 只是编译期的“别名声明”，不会加载文件，也不会创建对象。它告诉 PHP：“本文件中写 Shirt 时，指的是 Mattsmithdev\Shirt。”

如果需要同时使用两个同名类，可以用 as 起别名：

use Mattsmithdev\Shirt as BasicShirt;
use OtherVendor\Shirt as PremiumShirt;

$basic = new BasicShirt();
$premium = new PremiumShirt();

6.3解析规则：有没有前导反斜杠？

PHP 解析类名时，会根据“有没有前导 \”和“有没有 use”做判断。记住这几条就够了：

写法PHP 如何理解使用场景
new Shirt()当前命名空间下的 Shirt；如果顶部有 use Mattsmithdev\Shirt，则指导入的类当前文件常用写法
new \Mattsmithdev\Shirt()从根命名空间开始的完整路径只使用一次，或需要消除歧义
new Sub\Shirt()当前命名空间下的 Sub\Shirt当前命名空间的子命名空间

最常见的错误

在声明了 namespace App; 的文件里写 new DateTime()，PHP 会去找 App\DateTime，而不是内置的 \DateTime。要么写 new \DateTime()，要么在顶部 use DateTime;。

讲义还提醒：如果只是偶尔用一次另一个命名空间的类，完全限定名就够了；如果要反复使用，use 更简洁，而且不需要每次写前导反斜杠。

本章小结

  • namespace 写在文件最前面，给类加上虚拟目录。
  • 反斜杠 \ 分隔命名空间和类名；根命名空间用一个 \ 表示。
  • 完全限定名从 \ 开始；use 导入后可用短名。
  • 没有前导 \ 时，PHP 先按当前命名空间解析。
  • 同名类可以用 as 起别名。

Composer 与自动加载

不再为每个类写一行 require_once。Composer 按 PSR-4 规则把命名空间映射到目录，需要哪个类就加载哪个文件。

对应讲义：Composer · Autoloader · Autoloader: adding a library

本章目标

  • 理解 composer.json 在项目中的位置与作用；
  • 写出正确的 PSR-4 命名空间到目录映射；
  • 生成 vendor/autoload.php 并在入口文件中引入；
  • 用 composer require 安装第三方库并调用；
  • 能定位 “Class not found” 这类自动加载问题。

7.1Composer 到底做什么？

Composer 是 PHP 的命令行依赖管理工具。它主要做两件事：

  • 管理依赖：记录项目需要哪些第三方包，下载到 vendor/，并锁定版本；
  • 生成自动加载器：根据命名空间规则，生成 vendor/autoload.php，让 PHP 在需要某个类时自动找到对应文件。

项目根目录必须有一个 composer.json，它记录命名空间、类文件位置、依赖包和可选的命令行脚本。Laravel 等框架也使用 Composer。

my-project/
├── composer.json
├── composer.lock          # 首次安装后生成，锁定精确版本
├── public/
│   └── index.php          # 前端控制器
├── src/
│   └── Shirt.php
└── vendor/                # Composer 生成，不要手改
    ├── autoload.php
    └── composer/

7.2PSR-4：命名空间就是目录

PSR-4 是 PHP 社区推荐的自动加载规范。核心思想很简单：命名空间前缀映射到一个基础目录，子命名空间对应子目录，类名对应文件名。

在 composer.json 中写：

{
    "autoload": {
        "psr-4": {
            "Mattsmithdev\\": "src/"
        }
    }
}

注意 JSON 中的双反斜杠 \\：JSON 字符串里 \ 是转义字符，所以一个真实的命名空间分隔符要写成两个。映射建立后：

完整类名Composer 查找的文件
Mattsmithdev\Shirtsrc/Shirt.php
Mattsmithdev\Shop\Productsrc/Shop/Product.php
Mattsmithdev\Shop\Food\Dessertsrc/Shop/Food/Dessert.php

因此，类的命名空间必须和目录结构一致，文件名必须和类名一致（包括大小写）。例如 src/Shop/Product.php 里必须声明 namespace Mattsmithdev\Shop;，类名必须是 Product。

常见误区

PSR-4 的映射不是“文件路径随便写，Composer 会猜”。它是严格的约定：前缀去掉后，剩余命名空间按 \ 拆成目录，最后一段是文件名。少一层目录、大小写不一致，都会导致类找不到。

7.3生成并使用自动加载器

配置好 composer.json 后，在项目根目录运行：

composer dump-autoload

Composer 会创建 vendor/ 目录，并生成 vendor/autoload.php。它还会生成 vendor/composer/autoload_psr4.php，把你写的 PSR-4 映射编码进去。每次新增类或修改命名空间映射后，都要重新运行这条命令。

在入口文件 public/index.php 中，只需要引入一次自动加载器，然后就可以直接使用类：

<?php
require_once __DIR__ . '/../vendor/autoload.php';

use Mattsmithdev\Shirt;

$shirt1 = new Shirt();
$shirt2 = new Shirt();

print "shirt 1 type = {$shirt1->getType()}";

这一行 require_once 取代了之前每个类一行的写法：

require_once __DIR__ . '/../src/Shirt.php';
require_once __DIR__ . '/../src/Product.php';
require_once __DIR__ . '/../src/Car.php';
// ...

自动加载器只在 PHP 第一次遇到某个未定义的类时，才会按命名空间去查找文件。找到就加载，找不到就报 “Class not found”。它不会预先把所有类都读进来，所以性能更好，也不会受文件加载顺序影响。

7.4引入第三方库

需要新库时，用 composer require。例如安装 MathPHP：

composer require markrogoyski/math-php

Composer 会下载库到 vendor/，更新自动加载器，并把依赖写进 composer.json 的 require 段：

{
    "autoload": {
        "psr-4": {
            "Mattsmithdev\\": "src/"
        }
    },
    "require": {
        "markrogoyski/math-php": "^2.10"
    }
}

markrogoyski 是 vendor 名，math-php 是包名，它们不是 PHP 命名空间。它们只是 Composer 用来定位第三方包的标识。真正的类命名空间由包的作者声明，例如 MathPHP 的 MathPHP\Statistics\Average。

<?php
require_once __DIR__ . '/../vendor/autoload.php';

use MathPHP\Statistics\Average;

$numbers = [13, 18, 13, 14, 13, 16, 14, 21, 13];
$numbersString = implode(', ', $numbers);
$mean = Average::mean($numbers);
print "average of [ $numbersString ] = $mean";
average of [ 13, 18, 13, 14, 13, 16, 14, 21, 13 ] = 15

版本号 ^2.10 的含义是“允许 2.10 及以上、但小于 3.0 的版本”。这是 Composer 的语义化版本约束，具体规则可以查 Composer 文档。

工程习惯

vendor/ 通常不提交到 Git，但 composer.json 和 composer.lock 要提交。新环境拉下代码后运行 composer install，就能按锁文件安装完全相同的依赖版本。

预计用时：30–45 分钟 · 需要 PHP 8+ 与 Composer

项目目标

  • 建立 Shop 命名空间和 PSR-4 目录结构；
  • 让 Food 继承抽象类 Product，Dessert 再继承 Food；
  • 分别重写 __toString()，用 parent:: 复用父类输出；
  • 在入口文件只引入 vendor/autoload.php，循环输出商品清单。

8.1项目结构

shop/ ├── composer.json ├── public/ │ └── index.php └── src/ ├── Product.php ├── Food.php └── Dessert.php

先在 shop/ 目录中创建结构，然后写 composer.json：

{
    "autoload": {
        "psr-4": {
            "Shop\\": "src/"
        }
    }
}

这里的映射表示：Shop\Product → src/Product.php，Shop\Food → src/Food.php，依此类推。之后每个类文件的第一条语句都写 namespace Shop;。

8.2抽象父类 Product

Product 负责保存名称和价格，并规定所有商品都必须能转换成一个用于显示的字符串。它自己不完整，所以声明为 abstract。

<?php

namespace Shop;

abstract class Product
{
    public function __construct(
        protected string $name,
        protected float $price
    ) {
    }

    public function getName(): string
    {
        return $this->name;
    }

    public function getPrice(): float
    {
        return $this->price;
    }

    public function __toString(): string
    {
        return sprintf('%s ($%.2f)', $this->name, $this->price);
    }
}

属性提升让构造函数很简洁；protected 让子类可以使用这两个属性，但项目外部只能通过 getter 读取。构造函数没有做价格校验，作为练习，你可以把它改成“价格必须大于 0”。

8.3Food：在父类输出上追加信息

<?php

namespace Shop;

class Food extends Product
{
    public function __construct(
        string $name,
        float $price,
        private string $expiryDate
    ) {
        parent::__construct($name, $price);
    }

    public function __toString(): string
    {
        return parent::__toString() . " [expires {$this->expiryDate}]";
    }
}

Food 新增了保质期属性，并在构造方法里调用 parent::__construct($name, $price)，把共同部分交给父类。重写 __toString() 时，先拿到父类的 Sourdough ($6.50)，再追加保质期。

8.4Dessert：在 Food 之上再加一层

<?php

namespace Shop;

class Dessert extends Food
{
    public function __toString(): string
    {
        return 'Dessert: ' . parent::__toString();
    }
}

这里演示了两层继承：Product → Food → Dessert。Dessert 没有自己的构造方法，因此沿用 Food 的构造方法。调用 parent::__toString() 会先执行 Food 的版本，而 Food 又会执行 Product 的版本，形成一条链。

8.5入口文件：只引入自动加载器

<?php
require_once __DIR__ . '/../vendor/autoload.php';

use Shop\Dessert;
use Shop\Food;

$items = [
    new Food('Sourdough', 6.50, '2026-11-01'),
    new Dessert('Tiramisu', 8.75, '2026-10-30'),
];

foreach ($items as $item) {
    print $item . PHP_EOL;
}

注意这里没有任何 require_once 指向 Product.php、Food.php 或 Dessert.php。Composer 的自动加载器会根据对象的完整类名去 src/ 下找文件。

8.6运行

composer dump-autoload
php public/index.php

预期输出：

Sourdough ($6.50) [expires 2026-11-01]
Dessert: Tiramisu ($8.75) [expires 2026-10-30]

  1. 先看完整报错

  2. 确认文件真的被加载

    在入口文件临时 var_dump(__DIR__);，确认相对路径没有跑偏。自动加载项目先确认 vendor/autoload.php 存在。

    Shop\Food 必须在 src/Food.php，且文件内写 namespace Shop;。大小写必须一致。

  4. 重新生成自动加载器

  5. 检查可见性

    外部代码访问 private / protected 属性会失败。问自己：这个访问应该由谁负责？通常答案是类自己的方法。
