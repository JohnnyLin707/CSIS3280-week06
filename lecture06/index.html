Classes and object

What a class declaration establishes, and how an object is created

  • A class declaration defines a class:
    • It lays out the properties (variables) each object of that class will have,
    • as well as the methods (functions) that can act upon those properties.
    • also establishes any relationship
  • Class names and class declaration filenames always start with a capital letter
    • Class name convention uses PascalCase
  • PHP keyword new is used to create/instantiate an object of a class, e.g., $myObject = new ClassName()
    • variable $myObject doesn’t actually contain the object itself, but rather a reference to the object
    • The object operator (→) is used to access properties and methods of that object
class Product
{
    public string $name;
    public float $price;
}

PHP code declaring a class. Notice the capital letter of the class name. The file is also stored in capital letter, i.e., src/Product.php

Private properties and accessor methods

Using private with getters and setters to enforce validation

  • Declaring a property to be private is a good practice to enforce validation
    • They need public accessor methods (setter or getter)
  • The default visibility for class members is public
  • Other visibility is called protected, which means that the member is accessible within the ‘family’ inheriting the same parent class
  • Getter and Setter method can be declared as the accessor methods
Slide note

Notice the use of this keyword

class Product
{
    private string $name;
    private float $price;

    public function getName(): string
    {
        return $this->name;
    }

    public function setName(string $name): void
    {
        $this->name = $name;
    }

    public function getPrice(): float
    {
        return $this->price;
    }

    public function setPrice(float $price): void
    {
        $this->price = $price;
    }
}

Private properties and accessor methods

The setter rejects a negative price before it reaches the property

Assessor method can be used to validate the values assigned to the object properties

class Product
{
    private string $name;
    private float $price;

    public function getName(): string
    {
        return $this->name;

    public function setName(string $name): void
    {
        $this->name = $name;

    {

Constructor magic method

__construct() runs when an object is created

  • Unlike any other programming language, a constructor method in PHP does not have similar name at its class name
  • The __construct() magic method
    • Overrides default behavior of an object
    • It needs to be declared first within the class
    • It can provide initial values for object properties by linking the parameters sent when creating the object
    • It can simplify the class declaration through ‘promotion’ since the class property can be declared and assign within the magic method
Slide note

Notice the use of setter methods within __construct() magic method

class Product
{
    private string $name;
    private float $price;

    public function __construct(string $name, float $price)
    {
        $this->setName($name);
        $this->setPrice($price);
    }
}
$product1 = new Product('hammer', 9.99);
print 'product 1 name = ' . $product1->getName();
print ", and price = {$product1->getPrice()}";

Custom method and virtual attributes

Methods that calculate new information instead of returning a stored property

  • We can create custom methods to provide useful information for our class
  • Custom methods can act as virtual attributes
    • Instead of providing a variation on an existing property we can perform calculations to arrive at a completely new piece of information
    • For example, if our class’s property is about date or timestamp, we can have a custom method to create virtual attributes related to age

Inheritance and Subclasses

Shared members are defined once in the superclass

  • Inheritance is the capability of one or more classes, called subclasses, to automatically have all the same properties and methods as another class, called a superclass.
    • We can define any general, shared members only once, in the superclass.
    • Objects of the subclasses inherit those properties and methods
    • The subclasses will also have whatever properties and methods are specific to the individual subclasses.
  • Subclasses can also override the superclass’s methods

Protected Visibility

Accessible to subclasses, closed to the rest of the project

  • When method/property is protected
    • it becomes accessible to any subclasses that inherit it,
    • but it can’t be accessed by code elsewhere in the project
  • The protected visibility designation is more restrictive than public but is less restrictive than private
class Vehicle
{
    private string $makeModel;
    private int $numPassengers;
    private float $topSpeed;

    public function getMakeModel(): string
    {
        return $this->makeModel;
    }
}
class Car extends Vehicle
{
    public string $bodyShape;

    public function getMakeModelShape(): string
    {
        return "$this->makeModel, $this->bodyShape";
    }
}
$car1 = new Car();

$car1->bodyShape = 'Sedan';
$car1->setMakeModel('Ford Mustang');
$car1->setNumPassengers(5);
$car1->setTopSpeed(150);

print $car1->getMakeModelShape();
Slide note

$makeModel is private, the Car subclass cannot access the superclass’s property. Your code will produce a warning. Its visibility should be changed to protected to avoid the warning

Abstract Classes

A base class that exists only to be inherited

  • An abstract class is one that will never be used to create objects
    • It is declared so their members (properties and methods) can be inherited by subclasses, e.g., the Vehicle class in our examples is an abstract class
  • An abstract class can be used to declare static members, properties, or methods that relate to the class as a whole rather than to individual objects.
Slide note

You should use abstract keyword to specify the purpose of a class

abstract class Vehicle
{
    protected string $makeModel;
    private int $numPassengers;
    private float $topSpeed;

    public function getMakeModel(): string
    {
        return $this->makeModel;
    }

    public function setMakeModel(string $makeModel): void
    {
        $this->makeModel = $makeModel;
    }
}

The Liskov Substitution Principle

A subclass must be usable anywhere its superclass is expected

  • The method that was override can have identical signature
  • Liskov substitution principle (LSP) stated that that you must be able to substitute an object of a superclass with an object of a subclass without creating any unexpected behavior.
    • Make a mandatory parameter optional - For example, a superclass method validUser(int $minAge), could be overridden by a subclass method that provides a default value, e.g., validUser(int $minAge = 18).
    • Add new optional parameters - Method validUser(int $minAge) superclass method could be overridden by a subclass method that adds another optional parameter (with a default value), such as validUser(int $minAge, int $maxAge = 65).
    • Return a more specific type - If a superclass has a getRandomFood() method that returns a reference to a Food object, this method could be overridden by a subclass method that returns a Dessert object instead (where Dessert is a subclass of Food). This is aka covariance.
    • Declare a parameter type to be less specific - For example, if a superclass has a method that takes a Dessert object as a parameter, a subclass could override it with a method that instead takes a Food object as a parameter. This is aka contravariance.

Augmenting Inherited Behavior

Call the parent method, then add to its result

  • The subclass Dessert augment its parent __toString() method by adding into the $message
  • Notice the use of scope-resolution operator (::)
class Food
{
    protected string $name;

    public function __construct(string $name)
    {
        $this->name = $name;
    }

    public function __toString(): string
    {
        return "(FOOD) $this->name";
    }
}
class Dessert extends Food
{
    public function __toString(): string
    {
        $message = parent::__toString();
        $message .= " I am a Dessert!";
        return $message;
    }
}

The Final keyword

Preventing a method from being overridden — and when not to seal a class

  • You can use the final keyword to the declaration of a method to prevent the method from being overridden by a subclass.
  • Using the final keyword on a class is not recommended, except
    • if you have an API library and you don’t want to allow or encourage programmers to expect different behaviors besides those declared in the API.
    • to help prevent code from breaking between versions and across updates; when a class is final, changes to the class’s internal implementation won’t have any unintended consequences outside the class.
class Product
{
    protected int $skuId;
    private string $description;

    public function __construct(int $skuId, string $description)
    {
        $this->skuId = $skuId;
        $this->description = $description;
    }

    public function getSkuId(): int
    {
        return $this->skuId;
    }

    public function getDescription(): string
    {
        return $this->description;
    }

    final public function setSkuId(int $skuId): void
    {
        if ($skuId > 0) $this->skuId = $skuId;
    }
}

Namespaces

A virtual hierarchy of directories for classes

  • Namespaces is a kind of virtual hierarchy of directories for classes, used to prevent class name collisions.
    • Classes are organized within namespaces and sub-namespaces,
  • A backslash character (\) separates namespaces, sub-namespaces (if any), and the class name. For example, \MyNamespace\MySubNamespace\MyClass
  • Classes that are built into the PHP language are in the root namespace, identified by a single backslash character
  • To declare the namespace of a class, use the namespace keyword followed by the namespace’s name.
    • This should be the first line of PHP code in the class-declaration file
namespace Mattsmithdev;

class Shirt
{
    private string $type = 't-shirt';

    public function getType(): string
    {
        return $this->type;
    }

    public function setType(string $type): void
    {
        $this->type = $type;
    }
}

Slide 24

Namespaces

Fully qualified names versus a use statement

  • To use a namespace:
    • Include the namespace when referencing the class; this is called using the fully qualified name of the class. For example: new \Mattsmithdev\Shirt().
    • Include a use statement before invoking the class without a backslash; this is called using qualified name. For example, use Mattsmithdev\Shirt
$shirt1 = new \Mattsmithdev\Shirt();
$shirt2 = new \Mattsmithdev\Shirt();

print "shirt 1 type = {$shirt1->getType()}";
use Mattsmithdev\Shirt;

$shirt1 = new Shirt();
$shirt2 = new Shirt();

print "shirt 1 type = {$shirt1->getType()}";
Slide note
  • Without using the initial backslash, PHP will assume you’re referring to a class or sub-namespace of the current namespace
  • if you are referring to a class or sub-namespace of the current namespace, you shouldn’t include a backslash before the class or sub-namespace.
  • If you’re using a class from another namespace only once, you can use their fully qualified name, including the initial backslash.
  • If you’ll need to refer to the class several times, however, writing a use statement is more efficient, i.e., no initial backslash is needed.

Composer

The command-line tool that manages class files, namespaces, and dependencies

  • Composer is command line tool to support OOP PHP
    • It helps with loading class and function declaration files
    • It facilitates working with classes from different namespaces.
    • It is used in Laravel framework
  • A composer.json file is needed to house all the information Composer needs to know about the project.
    • It records of the namespaces and class locations for your own code, as well as of the third-party packages that the project depends on.
    • It can have a command line aliases
  • The composer.json text file must be located at the top level of your PHP project directory
{
    "scripts": {
        "hello": "echo Hello World"
    }
}
$ composer hello
> echo Hello, world!
Hello, world!

Slide 26

Autoloader

PSR-4 maps namespaces to directories, so files load only when needed

  • An autoloader is a system that automatically retrieves class-declaration files whenever they’re needed
  • PSR-4 recommendation
    • the base directory containing the classes of each namespace should be declared
    • any sub-namespaces will be assumed to have corresponding subdirectories within the declared base directory of the namespace.
  • Steps to use Composer autoloader
    • Declare the base directory for each namespace in the project’s composer.json file.
    • Tell Composer to create or update its autoloader script.
    • Add a require_once statement for the autoloader script at the beginning of the project’s public /index.php front controller. This single require_once statement replaces the separate require_once statements for each individual class.
{
    "autoload": {
        "psr-4": {
            "Mattsmithdev\\": "src"
        }
    }
}

Autoloader

Generating vendor/autoload.php and requiring it from the front controller

  • To create a class autoloader, run the following: 
    composer dump-autoload
  • This will create vendor folder and a file vendor/autoload.php and a vendor/composer folder containing several more scripts, including autoload_psr4.php, which encodes our PSR-4-compliant declaration
  • The front controller can instead require the autoloader file
require_once __DIR__ . '/../vendor/autoload.php';

use Mattsmithdev\Shirt;

$shirt1 = new Shirt();
$shirt2 = new Shirt();

print "shirt 1 type = {$shirt1->getType()}";

Slide 28

Autoloader: adding a library

Vendor and package names are Composer identifiers, not PHP namespaces

  • To add a new library, we need to tell composer that we require a new one. For example: 
    composer require markrogoyski/math-php
  • Composer will download the library, put them in the vendor folder, update the autoloader and record its dependency in composer.json file
  • The vendor name, i.e., markrogoyski, and package name, i.e., math-php are not namespaces.
    • These are names that Composer uses to identify and locate the third-party scripts to be added to the project
{
    "autoload": {
        "psr-4": {
            "Mattsmithdev\\": "src"
        }
    },
    "require": {
        "markrogoyski/math-php": "^2.10"
    }
}
require_once __DIR__ . '/../vendor/autoload.php';

use MathPHP\Statistics\Average;

$numbers = [13, 18, 13, 14, 13, 16, 14, 21, 13];
$numbersString = implode(', ', $numbers);
$mean = Average::mean($numbers);
print "average of [ $numbersString ] = $mean";
