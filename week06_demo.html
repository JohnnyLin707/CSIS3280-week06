老师到底补全了哪些代码？

左半边是 week06_starter 发下来的原代码（只有注释骨架或空文件）， 右半边是 week06_demo 里老师补全后的完整代码。 右栏绿色底是老师新写的代码、黄色底是被改动的一行， 琥珀色中文注释逐处说明这些补全代码的功能用途；代码框外面的空白区 再解释「为什么必须补」「老师的用意」「用到的 PHP 用法」。关闭右上角的「显示中文注释」即可看到与 demo 逐行一致的原始代码。

老师新增的代码 老师改动的一行 中文注释（教学注解，demo 原文件里没有） starter 留空 / 待改 两边原本就一样
#文件类型老师补全 / 改动了什么
1CH18/src/Product.php补全2 个 private 类型化属性、__construct()、__toString()、4 个 getter/setter，setPrice() 里加非负校验
2CH18/public/index.php补全从只有 <?php 变成可运行入口：require_once、实例化、setter 调用、字符串插值输出
3CH19/demo1/src/Vehicle.php改 1 行private → protected，让子类 Car 能直接读 $makeModel
4CH19/demo1/src/Car.php新增文件starter 里没有这个文件；新增 extends Vehicle 子类、$bodyShape 与 getMakeModelShape()
5CH19/demo1/public/index.php补全0 字节空文件 → 完整入口脚本：按序 require、new Car()、public 直接赋值 + setter、print / var_dump
6CH19/demo2/src/Food.php未改动两个文件夹内容完全相同；它是继承的起点，用来对照子类只写「差异」
7CH19/demo2/src/Dessert.php补全构造方法体与 __toString() 方法体：parent:: 调用 + .= 累加 + return（方法增强 / 重写）
8CH19/demo2/public/index.php补全从只有 <?php 变成入口脚本：先父类后子类 require、new Dessert、print、var_dump

合计：demo 比 starter 多 1 个文件（Car.php）；4 个文件从空壳 / 空文件补成可运行脚本； 1 个文件只改一个关键字；1 个文件（Food.php）老师完全没动。
